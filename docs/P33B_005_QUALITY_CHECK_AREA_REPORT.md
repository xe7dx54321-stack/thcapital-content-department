# P33B-005 Quality Check Area Report

## 页面定位

看"这篇稿子为什么通过 / 为什么有问题"。

这里不是系统运维页。

## 绝对不能出现

- LaunchAgent 状态
- heartbeat
- Runtime PID
- OpenClaw 冲突详情
- path-audit

## 页面结构

### A. 质量总览

显示：
- 质量评级：PASS / ACTIONABLE / FAIL
- 是否可人工审阅：是 / 否
- 阻断问题数量
- 非阻断问题数量

### B. 内容质量 Checklist

只展示内容质量相关项：
- 选题是否成熟
- 标题是否像公众号标题
- why now 是否清楚
- 核心读者问题是否清楚
- 证据是否足够
- 故事线是否清晰
- 是否有明确观点
- 是否有反方 / 限制
- 是否有 AI 味
- 是否有伪造引用风险
- 是否出现 target price

每项展示：
- 通过 / 警告 / 失败
- 一句话原因

### C. 证据检查

显示：
- 核心证据数量
- 一手来源数量
- 二手来源数量
- 弱信号数量
- 需要人工确认的证据

弱信号必须明确标注，不混成硬证据。

### D. 人工审阅清单

直接展示用户要检查的事项：
1. 这个标题是否足够具体？
2. 开头是否值得继续读？
3. 关键证据是否真实可靠？
4. 有没有明显 AI 味？
5. 是否值得人工改后发布？

## 数据来源

来自 `workbench_view_model.quality_check`。
